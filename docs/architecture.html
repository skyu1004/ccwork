📝 Notes App 아키텍처

src/ 디렉토리를 분석해 정리한 구조도. 코드: React 19 + TypeScript + Vite, 상태: useState + Context, 서버: JSON Server.

1. 모듈 의존성 2. 컴포넌트 관계 3. 상태 흐름 4. UI 상태 전이 5. 동작 시퀀스

1. 모듈 의존성 (import 관계)

UI 상태 (App) 서버 데이터 (Context) 폼 상태 (NoteEditor)
  • 변경 함수는 API가 성공한 뒤에 로컬 state를 갱신한다. 낙관적 업데이트와 재조회는 없다.
  • error는 초기 fetchNotes 실패에만 쓰인다. 저장/삭제 실패는 컴포넌트가 catch해서 console.error로만 남긴다.

4. UI 상태 전이 (selectedNoteId × isCreating)

NoteEditor가 무엇을 보여줄지는 두 값의 조합으로 결정된다.

stateDiagram-v2
  [*] --> Idle
  Idle: 안내 화면
  Idle: id = null · isCreating = false
  Creating: 새 노트 폼
  Creating: id = null · isCreating = true
  Editing: 편집 폼
  Editing: id = 선택값 · isCreating = false

  Idle --> Creating: 새 노트 클릭
  Idle --> Editing: 노트 선택
  Creating --> Editing: 노트 선택
  Editing --> Creating: 새 노트 클릭
  Editing --> Editing: 다른 노트 선택
  Creating --> Idle: 저장 / 취소 (onDone)
  Editing --> Editing: 저장 / 취소 (onDone)
  • 새 노트 저장 후 Creating → Idle이 되어 방금 만든 노트가 선택되지 않는다. App.handleDone 주석("선택 상태는 유지")과 다른 동작이다. (CLAUDE.md 알려진 불일치 #5)
  • 편집 중 "취소"는 onDone만 호출하므로 폼 값이 원래대로 복원되지 않는다. (알려진 불일치 #6)

5. 동작 시퀀스

초기 로드, 저장(생성/수정), 삭제 세 가지 흐름이다.

sequenceDiagram
  autonumber
  actor U as 사용자
  participant App
  participant L as NoteList
  participant E as NoteEditor
  participant C as NotesContext
  participant A as api/notes.ts
  participant S as JSON Server

  rect rgba(47, 93, 158, 0.10)
    Note over C,S: 초기 로드
    C->>A: fetchNotes() (useEffect, 마운트 시 1회)
    A->>S: GET /notes
    S-->>A: Note[]
    A-->>C: Note[]
    C->>C: setNotes · setLoading(false)
    C-->>L: notes 변경으로 리렌더
  end

  rect rgba(47, 138, 77, 0.10)
    Note over U,S: 저장 (생성 / 수정)
    U->>E: 저장 클릭
    E->>E: 제목 검증 · setSaving(true)
    E->>C: createNote(title, content) / updateNote(id, updates)
    C->>A: api.createNote / api.updateNote
    A->>S: POST / PATCH (createdAt · updatedAt은 클라이언트가 채움)
    S-->>A: 저장된 Note
    A-->>C: Note
    C->>C: setNotes(prev => 추가 또는 교체)
    C-->>E: resolve
    E->>App: onDone()
    App->>App: setIsCreating(false)
    E->>E: finally setSaving(false)
  end

  rect rgba(162, 59, 132, 0.10)
    Note over U,S: 삭제
    U->>L: NoteItem의 삭제 클릭
    L->>C: deleteNote(id)
    C->>A: api.deleteNote(id)
    A->>S: DELETE /notes/:id
    S-->>A: 200 OK
    C->>C: setNotes(prev => prev.filter(...))
    C-->>L: 목록 리렌더
  end
